{% comment %} Integration row — one connectable service, its state, and what you can do with it. Props: integration an entry from the integrations view's context provider which brand mark to show (see ) Slots: actions the connect / configure / disconnect controls Connection state is stated in words as well as colour, and the "awaiting first event" state is spelled out rather than hidden in a tooltip, because it is the single most common reason a new workspace thinks Notipus is broken. `event_state` is decided in Python (IntegrationService._event_state) and is None for anything whose event state we do not track, so this row never has to guess from a missing key. It used to, with `{% if x is defined %}` — Jinja, in a Django template — and got it exactly backwards: sources that were receiving events showed no badge, destinations claimed "No events yet" forever. The row stacks in a narrow container and goes side by side in a wide one, and every row in a list flips at the same point — actions are never inline on one row and below on the next. Two things this deliberately is not: `flex-wrap`, because wrapping is decided per row from its own content, so a one-button row kept its action inline while the row under it dropped three buttons onto a second line. Worse, a `flex-wrap` row whose text column is a bare `flex-1` reads as zero-width to the wrap algorithm, so it never wraps at all and crushes the text to a word per line — what this component did at ~500px. A viewport breakpoint (`sm:`), because the container is what actually constrains the row. The integrations page puts cards in a two-column grid, so at a 1280px viewport these rows live in a 530px card; keyed to the viewport they would go side by side and crush the Slack row's text to 153px. `@2xl` is ~672px of container, which leaves the widest action group (Configure / Send test / Disconnect) about 240px of text beside it. {% endcomment %}
